# BaikalStage CRM · v1.6.0

Веб-CRM для проката ивент-оборудования: коммерческие предложения (сметы), склад с QR-единицами, ремонты, календарь и срост, зарплата, бухгалтерия и база клиентов.

**Стек:** Next.js 16 · React 19 · Prisma 6 · PostgreSQL 16 · NextAuth · Caddy (HTTPS) · Docker

## Changelog

### v1.6.0 — 2026-09-20

Апдейт относительно **v1.5.0** (1 сентября → 20 сентября). Главное — **рабочая мобильная версия** и календарь, которым можно пользоваться с телефона.

#### Оболочка на телефоне

- Нижнее меню из четырёх иконок: **календарь / уведомления / моя ЗП / все разделы**
- Верхняя панель на телефоне убрана; отступ под Dynamic Island — `safe-area`
- Колокольчик из шапки переехал на нижнее меню (бейдж непрочитанных)
- После клавиатуры и выгрузки Excel меню остаётся у нижнего края экрана, без чёрной полосы
- Шиты сметы и спеки открываются на всю высоту и не уезжают под нижнее меню
- QR-сканер ремонта открывается по центру, не снизу

#### Календарь

- Цвета полосок: посчитано — синий, подтверждено — зелёный, оплачено / завершено — золотой, отменено — серый, выходной — красный
- Оплаченное КП в сетке рисуется как завершённое
- На iPhone в ячейке дня помещается **до 6 полосок**; лишнее — `+N` у даты
- Сетка всегда **6 рядов**: свайп влево / вправо листает месяц, размер полосок не прыгает
- Тап по дню (в том числе по полоске) открывает список мероприятий этого дня
- На телефоне у фильтров остаются только точки, без подписей
- Даты мероприятия и монтажа в карточке проекта можно править сразу, если вы менеджер, админ или бригадир

#### Сметы и спецификации

- Справочники и сметы на телефоне — **карточки**, не широкие таблицы
- Компактная смета / спека: вкладки зон с контуром «папки»
- Кнопки «Добавить из каталога / + Раздел / + Позиция» выше; строка оборудования выше
- Предупреждение о нехватке склада и список вакантных слотов персонала сворачиваются (и на компьютере, и на телефоне)
- «Импорт из сметы» в спецификации виден без режима правки, если есть право редактировать спеку
- Спека по-прежнему **снимок**: смена статуса КП её не пересобирает

#### Уведомления и зарплата

- Ссылка «Неоплаченные проекты» из уведомлений убрана — счета остаются обычными карточками
- «Прочитать все» стоит в один ряд с фильтрами Все / Непрочитанные
- В «Моя ЗП» итог больше не залезает выше заголовка раздела

### v1.5.0 — 2026-09-01

Апдейт относительно **v1.4.0** (25 августа → 1 сентября). Коммит `0abad1a`: **~122 файла**, **+11 300 / −530** строк.

Главное: календарь сроста стал учитывать **даты зон**, а не только длительность мероприятия. Плюс справочник фрилансеров, оплаты, импорт смет из Excel и склад по пику дня.

Пошаговые сценарии — в блоке [Туториалы: календарь и срост](#туториалы-календарь-и-срост) ниже.

#### Срост и календарь занятости

- Лента `/roster` рисует слот **по датам зоны**: если зона «Зал» только 12–13 сентября, люди этой зоны не растягиваются на все дни КП
- Пустые слоты монтажа / демонтажа можно скрыть фильтром **«Пустые монтаж»**
- Панель справа: **Сотрудники / Фрилансеры**, поиск, стрелки и Enter на выбранный слот
- Клик по дню открывает повестку дня; клик по полоске — карточку проекта или записи
- Конфликты те же: выходной блокирует, пересечение смены / аренды / задачи — предупреждение

#### Зоны с раздельными датами

У `QuoteZone` появилось поле `workingDayIndexes` (1-based дни мероприятия; пусто = все дни).

- В смете при длительности ≥ 2 дней — **«Даты зоны»** на активной вкладке
- Во вкладке **Команда**: переключатель **По дням / По зонам**. В режиме зон вместо «День 1…N» — кнопки с именами зон и датами
- Число строк персонала — **по количеству проданных услуг**, привязанных к ставке, **не** qty × дни мероприятия
- Склад считает **пик одновременной занятости по дням**: непересекающиеся зоны не суммируются в «единицы × дни»

#### Фрилансеры и оплаты

- Справочник **База данных → Фрилансеры** (`/freelancers`): ФИО, комментарий, специальности со своими сменой/часом
- Назначение по ФИО создаёт карточку, если её ещё нет; в сросте фрилансеры фильтруются по специальностям карточки
- **Учёт → Оплаты** (`/payouts`): доступ включает админ галочкой `canAccessPayments` в карточке пользователя. ЗП штата за прошлый месяц и выплаты фрилансерам с CONFIRMED/COMPLETED мероприятий

#### Сметы, ставки, каталог

- Импорт КП из Excel (`.xlsx` / `.xlsm`, формат Артема) со списка смет — позиции матчятся с каталогом
- В **Ставках** к специальности привязываются **несколько услуг** каталога: любая из них в смете создаёт запрос на эту должность
- В смете позицию можно **заменить**, перетащив позицию каталога на поле замены
- Разделы каталога переносятся целиком (вложенные папки и позиции едут с родителем)
- У физической единицы — свой склад `EquipmentUnit.owner` (SHM / DK / NE)

#### Калькуляции

- Список калькуляций: **сводный Excel** по выбранным событиям, листы NE / ДК / ШМ

#### Схема и API (дельта к 1.4)

- `QuoteZone.workingDayIndexes`
- `Freelancer`, `FreelancerSpecialty`
- `Payout` (`STAFF_MONTH` / `FREELANCER_EVENT`)
- `Specialty` ↔ несколько `CatalogItem` (услуги / персонал)
- `EquipmentUnit.owner`, `User.canAccessPayments`
- Маршруты: `/freelancers`, `/payouts`, `GET/POST /api/quotes/import-excel`, `PATCH /api/quotes/[id]/zones/[zoneId]` (`workingDayIndexes`)

#### Тесты (новые и расширенные)

`roster`, `quote-assignment-days`, `quote-assignment-slots`, `quote-excel-import`, `payouts`, `freelancer-directory`, `catalog-move`, `calc-summary`, `specialty-link`, `stock` (пик по дням)

### Туториалы: календарь и срост

Два разных экрана. **Календарь** (`/calendar`) — что происходит в компании. **Срост** (`/roster`, меню **Учёт**) — кто из людей на это поставлен. Сотрудник срост не видит; менеджер и бригадир — да.

#### 1. Календарь: день, запись, сводка

1. После входа открывается календарь месяца.
2. Фильтры над сеткой: статусы КП (Посчитано / Подтверждено / Отменено / Завершено) и типы записей (Аренда / Задача / Выходной). Погашенный чип скрывает тип.
3. **Пустой день** — клик открывает меню:
   - **Проект** — новое КП на эту дату (менеджер)
   - **Аренда оборудования** — резерв склада без сметы (менеджер)
   - **Задача** — исполнители, можно отметить выполненной в сводке (менеджер, бригадир)
   - **Выходной** — блокирует назначение этого человека в сросте и в команде (менеджер, бригадир)
4. Если на дне уже есть полоски — клик открывает **повестку дня**, а не меню. Создать ещё запись: кнопка «+» в шапке или на телефоне.
5. Клик по полоске КП открывает карточку проекта (ТЗ, команда, файлы, чат). Клик по аренде / задаче / выходному — карточку записи.
6. Справа (на компьютере) — **сводка**: неоплаченные, пустые слоты персонала, задачи, аренды, «мои» мероприятия, погода. Задачу можно закрыть галочкой, не открывая карточку. Колокольчик на сводке — есть незакрытые задачи или вакансии.

Цвета полосок КП совпадают со статусом (подтверждено — зелёный, оплачено — золотой). Аренда — коричневая, задача — охра, выходной — красный. На телефоне месяц листается свайпом.

#### 2. От сметы к корректному сросту

Чтобы в сросте человек стоял **в те дни, когда зона реально работает**, а не на всю длительность КП:

1. **База данных → Ставки.** У специальности укажите услуги каталога (например «Видеоинженер» → позиции «Видеоинженер» / «Video»). Одна услуга — только у одной ставки.
2. В КП задайте **даты мероприятия** (и при необходимости монтаж / демонтаж).
3. Создайте **зоны** вкладками сметы. Если зоны в разные дни — на вкладке зоны выберите **«Даты зоны»** (диапазон внутри дат КП). Пустые даты зоны = зона на все дни мероприятия.
4. В зоны положите услуги персонала. Количество в смете = сколько человек нужно **на эту зону**, а не «qty × число дней».
5. Вкладка **Команда**:
   - **По дням** — вкладки «День 1…N». Одинаковый состав на всех днях схлопывается в общий список.
   - **По зонам** — кнопки с именами зон. Выберите зону, при необходимости поправьте её даты тем же «Даты зоны». Строки появятся по проданным услугам со ставкой.
6. Назначьте штат или фрилансера, либо оставьте пустой слот — он всё равно приедет в срост.
7. Откройте **Учёт → Срост**. Полоска этого человека (или пустая должность) лежит только на датах зоны. Монтажники рисуются серым на датах монтажа / демонтажа, отдельно от шоу.

Без дат мероприятия зона в срост не попадает: сначала даты КП, потом даты зоны.

**Пример.** КП 10–12 сентября, три дня. Зона «Площадка А» — 10-е, зона «Площадка Б» — 11–12-е. В смету в каждую зону положили 1× «Звукооператор». В команде режим **По зонам**: две строки звука, не три. В сросте 10-го виден слот зоны А, 11–12-го — зоны Б. Склад тоже смотрит пик дня: один пульт на А и один на Б в разные дни = резерв 1, а не 2.

#### 3. Срост: назначить, сдвинуть, снять

1. **Учёт → Срост.** На экране ~10 дней: текущая неделя и начало следующей. **Сегодня** / стрелки двигают окно.
2. Фильтры-точки: Мероприятие / Аренда / Задача; фирмы **ШМ / ДК / NE** (по менеджеру КП); **Пустые монтаж** — пустые слоты М/Д.
3. Кнопка с силуэтом справа открывает панель людей.
   - Вкладка **Сотрудники** или **Фрилансеры**.
   - Поиск по фамилии. Полоска заработка — сколько человек уже набрал за месяц относительно коллег.
   - «Занят» — на видимых датах уже есть слот.
4. **Поставить человека**
   - Клик по пустому слоту (обводка должности) — слот выбран, в панели подсветка «Слот: …». Клик по человеку или Enter назначает.
   - Либо перетащите человека из панели на слот или на день.
5. **Передвинуть смену** — потяните цветную полоску на другой день внутри окна мероприятия / зоны.
6. **Растянуть** — потяните левый или правый край. Для шоу это дни зоны; для монтажа — окно монтажа или демонтажа.
7. **Снять** — крестик на полоске или перетащите полоску обратно в панель людей.
8. Клик по дню — список слотов этого дня. Клик по назначенной полоске — карточка КП.

Выходной на дату назначения система не пропустит. Пересечение с другой сменой, арендой или задачей — диалог «назначить всё равно».

Фрилансера без специальности в карточке панель сроста не покажет на слот этой должности: сначала **База данных → Фрилансеры**, привяжите ставки.

#### 4. Команда КП без сроста

Тот же состав правится во вкладке **Команда** карточки КП:

- **Сотрудник** — должность, затем ФИО из штата с этой специальностью.
- **Фрилансер** — ФИО (подсказка из справочника), ставка смены, фирма для расходки.
- Монтажники — отдельный блок, маркеры **М** / **Д**. Клик в сросте на монтаж ставит только М, на демонтаж — только Д; оба дня — оба маркера.
- Замена человека на уже занятой должности — подтверждение.

Имеет смысл: состав набросать в команде (или оставить пустые слоты из сметы), а «кто свободен на этой неделе» смотреть уже в сросте.

#### 5. Аренда, задача, выходной и срост

| Запись в календаре | Кто создаёт | Что в сросте |
|---|---|---|
| КП / проект | менеджер | слоты команды и монтажа по датам зон |
| Аренда | менеджер | ответственный и исполнители на дату аренды |
| Задача | менеджер, бригадир | ответственный и исполнители |
| Выходной | менеджер, бригадир | в ленте занятости нет, но **блокирует** назначение |

Исполнителей аренды и задачи тоже можно ставить перетаскиванием в сросте.

#### Срост (`/roster`)

Новый раздел загруженности персонала — в меню **Учёт** у менеджера и бригадира. Сотрудник туда не ходит (`canAccessRoster` + проверка в `middleware`).

- Назначение **перетаскиванием** на слот, растягивание краёв (`/api/roster/span`), снятие крестиком
- Панель сотрудников справа; фильтры по типу записи и владельцам склада **SHM / DK / NE**
- Конфликты расписания (пересечение смен, выходной) — предупреждение
- Индикатор относительного заработка за выбранный месяц
- API: `GET /api/roster`, `POST /api/roster/move`, `POST /api/roster/span`
- Логика: `roster.ts`, `roster-server.ts`; тесты `roster.test.ts`

#### Назначения: дни, зоны, монтаж / демонтаж

Схема `QuoteAssignment` дополнена полями:

| Поле | Смысл |
|---|---|
| `zoneId` | зона сметы, из которой пришёл слот (можно сменить вручную) |
| `dayIndex` | рабочий день мероприятия, 1-based; `null` = все дни / монтажник |
| `onMount` / `onDemount` | флаги М / Д у монтажника; по умолчанию оба `true` |

Миграции: `assignment_zone`, `assignment_day_index`, `assignment_mount_duty`.

- Вкладка **Команда**: **День 1…N**; если состав одинаковый на всех днях — общий список
- Слоты из строк персонала сметы наследуют зону должности
- Монтажники отдельно от участников шоу; назначение на М или Д из сроста сливает маркеры в одну строку
- Копирование сметы, история и восстановление переносят зону, день и флаги М/Д
- Логика: `quote-assignment-days.ts`, `quote-assignment-slots.ts`, `quote-mount-duty.ts`

### Поток сметы

```mermaid
flowchart TD
  A[Менеджер создаёт смету] --> B[CALCULATED — Посчитано]
  B --> C[Клиент · площадка · даты · зоны · каталог]
  C --> D[Назначение: ставка / override / монтаж]
  D --> D1{Выходной у сотрудника?}
  D1 -->|да| D
  D1 -->|нет| E{Подтвердить?}
  E -->|CONFIRMED| F[Склад: сметы + аренды календаря]
  F -->|дефицит| F1[Сохранить + предупредить о субаренде]
  F -->|достаточно| G[Резерв на даты]
  F1 --> G
  G --> H[Календарь · карточка · файлы · чат]
  D --> R[Срост: слоты по датам зон]
  H --> I[После окончания: счёт / Неоплаченные]
  G --> L[COMPLETED]
  B --> M[CANCELLED — снимает резерв]
  D --> N[Моя ЗП + агентские agencyPercent]
  I --> O[Статистика / калькуляции]
```

### Поток склада и QR

```mermaid
flowchart TD
  P[Позиция каталога + stockQty] --> U[Единицы EquipmentUnit]
  U --> Q[QR /q/token — публичная карточка]
  Q --> R{Списать в ремонт}
  R -->|OPEN| S[inRepair · stock −1 · фото]
  S --> T{Закрыть / списать}
  T -->|CLOSED возврат| U
  T -->|DAMAGED / LOST| W[active=false]
  U --> Rent[Аренда календаря резервирует qty]
  U --> Quote[Подтверждённая смета резервирует qty]
```

**Цепочка вкратце**

1. Создать КП → «Посчитано», наполнить, назначить персонал (выходной блокирует).
2. Подтвердить → проверка склада (сметы + аренды); при дефиците сохранить предупреждение о субаренде.
3. В работе: календарь, ТЗ, файлы, чат; аренда/задачи/выходные живут рядом со сметами. Срост показывает людей только в даты их зоны.
4. Поломка: QR → ремонт → очередь `/repairs` → возврат или списание.
5. После события → «Неоплаченные»; деньги: ЗП, агентские %, калькуляции, прибыль клиента.

## Установка на сервер (Docker)

Нужны Docker и Docker Compose. Скрипт спросит домен (для HTTPS) и данные первого администратора.

```bash
./install.sh
```

После установки: `https://ВАШ_ДОМЕН`. Каталог в prod **пустой** — загрузите CSV/JSON из «База данных».

**Требования**
- свободные порты **80** и **443**
- домен с A/AAAA на IP сервера (Let's Encrypt через Caddy)

Сервисы: `db` (Postgres) · `app` (Next.js) · `caddy` (прокси + TLS).

Данные на диске хоста: `./data/postgres`, `./data/uploads`, снимки в `./backups`. Так их проще копировать на другой диск или сервер, чем из Docker-томов.

Если обновляете уже работающий сервер со старыми томами `pgdata` / `uploads`:

```bash
./scripts/migrate-volumes-to-data.sh
docker compose up -d
```

Сборка образа: `npx next build --webpack` (в Docker Turbopack сильно тормозит). На слабом VPS удобнее собрать образ на ноутбуке и загрузить.

### Бэкап и переезд

**Полный снимок** (Postgres + файлы `uploads`) — это disaster recovery и перенос на другой сервер. JSON на `/backup` копирует только справочники и **не** заменяет полный снимок.

Снимок: `backups/crm-full-YYYYMMDD-HHMM.tar.gz` (`manifest.json`, `postgres.dump`, `uploads/`).

```bash
./scripts/backup.sh                          # создать снимок, ротация 14 штук
BACKUP_KEEP=7 ./scripts/backup.sh
./scripts/backup-cron.sh                     # строка для crontab (ежедневно в 03:00)
./scripts/restore.sh --dry-run backups/crm-full-YYYYMMDD-HHMM.tar.gz
./scripts/restore.sh backups/crm-full-YYYYMMDD-HHMM.tar.gz
./scripts/restore.sh --yes backups/crm-full-YYYYMMDD-HHMM.tar.gz
```

В UI: **База данных → Экспорт / импорт** — «Создать снимок» и скачивание. Restore из браузера нет.

**Переезд на новый VPS (архив):**

```bash
# на старом
./scripts/backup.sh
scp backups/crm-full-*.tar.gz user@NEW:/var/www/bsg-crm/backups/

# на новом
./install.sh                                 # или git clone + docker compose up -d
./scripts/restore.sh --yes backups/crm-full-YYYYMMDD-HHMM.tar.gz
```

**Переезд «как есть» (диск):**

```bash
rsync -aH --numeric-ids ./data ./backups .env user@NEW:/var/www/bsg-crm/
# на новом: docker compose up -d
```

Каталог `./data` можно держать на втором диске или NAS (примонтировать в `./data`) — код менять не нужно.

**Справочники (JSON из UI):** страница `/backup` — обмен каталогом/клиентами между стендами, не полный бэкап.

### Обновление релиза на VPS

На слабом VPS (`next build` в Docker часто «висит» на шаге webpack 10–20+ мин или уходит в swap). Надёжнее собрать образ на ноутбуке:

```bash
# на ноутбуке, из корня репо
./scripts/docker-build-export.sh user@VPS:/var/www/bsg-crm
# на VPS:
cd /var/www/bsg-crm
gunzip -c crm-app.tar.gz | docker load
git pull   # compose/Caddy/миграции
docker compose up -d
```

Если всё же собираете на сервере:

```bash
git pull
# не используйте --no-cache без нужды
DOCKER_BUILDKIT=1 docker compose up -d --build
docker compose logs -f app
```

Если шаг `next build` снова стоит дольше ~25 мин — прервите, проверьте `free -h` (нужен swap ≥2G) и соберите образ на ноутбуке.

## Переменные окружения (prod `.env`)

| Переменная | Назначение |
|---|---|
| `DOMAIN` | Хост для Caddy / Let's Encrypt |
| `POSTGRES_USER` / `POSTGRES_PASSWORD` / `POSTGRES_DB` | Учётка Postgres |
| `DATABASE_URL` | Строка Prisma (`@db:5432` в compose) |
| `AUTH_SECRET` | Секрет NextAuth |
| `AUTH_URL` | `https://$DOMAIN` |
| `BOOTSTRAP_MODE` | `prod` — идемпотентный первый сид (без каталога) |
| `BOOTSTRAP_MANAGER_EMAIL` / `_PASSWORD` / `_NAME` | Первый администратор |

Файл `.env` создаёт `./install.sh`; в git он не коммитится.
